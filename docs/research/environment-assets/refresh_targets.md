# Refresh protocol

Last research access: 2026-09-20. Refresh immediately before any acquisition or
implementation, and whenever the engine, selected asset, license or visual gate
changes. Update changed source records and the decision; do not repeat a catalog
survey unless the admitted bundle fails. Preserve dated changes in a new
`diffs\YYYY-MM-DD-delta.md` only when a refresh actually occurs.

| Target | Recheck | Trigger / action |
| --- | --- | --- |
| Selected Poly Haven assets | Exact creator, free/CC0 metadata, file inventory, source version/bytes, map channels | Before download; changed source needs new reviewed receipt, not overwritten hash |
| Grass Ground | Recently published 2026-09-18 inventory and physical scale | Before material acquisition; retain old source identity if changed |
| Tree and grass source complexity | Export hierarchy, LOD count, actual per-mesh triangles and texture dependencies | Representative import; never infer from aggregate/scatter metadata |
| Fir Sapling fallback | Exact small asset identity, three-variant source hierarchy and young-tree scale | Primary-tree rejection; never substitute Fir Sapling Medium or claim a mature canopy without review |
| Leaf materials | Alpha, normal convention, two-sided response, mip behavior, supported wind data | Material spike, engine change or shimmering/halo report |
| Fab European Black Alder | Current price, full binding license/tier, formats, UE support, human claim prerequisites | Only if CC0 path fails or parent requests; currently excluded |
| Megascans entitlement | Exact previously acquired product and applicable terms | Only a human-authorized account review; old promotions do not establish rights |
| Native cloud content | Installed material names/parameters and cook dependencies | After offline editor gate only; keep existing sky if incompatible |
| Nanite/VSM/cloud docs | Version-specific limitations, experimental status and current guidance | Engine upgrade or failed performance spike |
| Offline authoring workflow | Accepted parent's exact executable/config/launch proof | Before any editor/commandlet/build/test; Shipping proof alone is insufficient |
| Capture validity | Lit/Lighting/ShaderComplexity, primary scale, viewport, actual candidate hash | Each visual batch and after save/load |
| Runtime budgets | Same-scene CPU/GPU/frame/VRAM/streaming evidence | Each admitted variant/density/wind/shadow/cloud change |
| Subjective outcome | Warm composition, believable silhouettes, resource readability, Jenny's reaction | Two bounded visual batches, then human review rather than endless iteration |

## Adversarial refresh triggers

Reopen the decision if a realistic tree cannot preserve material slots or fit
bounded LODs; if the fallback is a style mismatch; if ordinary traversal hides
resources; if clouds brighten night; if an import requires unsafe engine launch;
or if a claimed performance improvement disappears under moving sun/wind.

Publisher previews stay links unless separately licensed for redistribution.
New empirical results must distinguish source facts, measurements and judgment.
